# Камер Аудио Студио 2.0 Alpha

Настольная студия для Windows: сцены, виртуальная камера, обработка звука,
запись, субтитры и гости. Русский интерфейс со стандартной рамкой Windows.
Устройства, запись, сервер и расширения включаются вручную.

## Быстрый старт

Скачай [архив для Windows x64](https://github.com/Flory211/CamerAudioStudio/releases/download/v2.0-alpha/CamerAudioStudio-Windows-x64.zip),
распакуй его целиком и открой `CamerAudioStudio.exe`. Папка `_internal` должна
оставаться рядом с EXE.

1. Добавь источник слева. Выбери слой и настрой его справа.
2. На холсте перемещай слой и меняй размер за правый нижний угол.
3. Нажми **Превью**. Виртуальная камера включается отдельно и требует драйвера
   OBS Virtual Camera или Unity Capture. Превью и запись работают без него.
4. В **Звук** выбери вход и вывод. «Без микрофона» подходит для звуков и гостей.
   Вывод по умолчанию отключён. Для виртуального микрофона выбери установленное
   устройство виртуального аудиокабеля.
5. Сохрани проект через **Ctrl+S**. Повторное открытие проекта не включает устройства.

Видеоэффекты применяются к камере, экрану, окну, потоку и изображениям. Текст и
цвет оформляются через свойства слоя. Правила работают при включённом превью.
Время анимации начинается при входе в сцену.

## Ограничения альфы

- Системный loopback записывает **общий** звук. Раздельный захват каждого
  Windows-процесса в отдельный WAV пока не реализован. Панель Windows-приложений
  управляет реальными системными уровнями, но не создаёт отдельные дорожки процессов.
- Сеанс сохраняет исходное AVI, отдельные WAV/AVI, `recording.mp4`, `manifest.json`.
  Без поступившего звука аудиодорожки нет. При ошибке кодека исходники остаются,
  причина указана в `mux_error`. Повтор MP4 содержит звук, если микшер работал;
  вариант AVI — только видео.
- «Говорящий» определяется по движению рта, а не по личности голоса.
- Адаптивная детализация влияет на все выходы, включая запись и виртуальную камеру.
- Тесты с синтетическими данными не заменяют проверку реальных устройств и драйверов.

## Телефон и гости

Сервер по умолчанию выключен, при включении использует localhost. Для телефона
выбери локальную сеть и HTTPS, доверь локальному сертификату на своём устройстве
и самостоятельно разреши браузеру камеру/микрофон. ID подключённых гостей видны
в студии и выбираются в свойствах слоя. Пустой выбор — первая доступная камера.
Отключение конкретного гостя не подменяет его другим.

Ссылка содержит токен и разрешает просмотр/управление студией. Все методы пульта
требуют этот токен. Для Интернета нужен доступный HTTPS-адрес студии и при
необходимости свои STUN/TURN URL. Программа не покупает сервер и не открывает
порты роутера. TURN-пароль хранится только в памяти. Реальное подключение через
Интернет и доверие сертификату на телефоне требуют отдельной проверки.

## Модели и расширения

Подготовленная сборка включает локальные Selfie Segmenter, Face Landmarker и
Vosk small Russian. Пути подставляются автоматически; модели не включаются
до выбора соответствующей функции. Подготовка из исходников:

MediaPipe SDK отправляет техническую статистику использования Google. Поэтому
замена фона и мимика требуют отдельного согласия в «Инструменты → ИИ»; оно
не сохраняется в проекте и сбрасывается при его смене. Без согласия SDK не
запускается, базовый Haar-трекинг доступен. См. [объяснение разработчика SDK](https://github.com/google-ai-edge/mediapipe/issues/6291).

```powershell
.venv\Scripts\python.exe tools\download_models.py
```

Источники: [Google Image Segmenter](https://developers.google.com/edge/mediapipe/solutions/vision/image_segmenter),
[Google Face Landmarker](https://developers.google.com/edge/mediapipe/solutions/vision/face_landmarker),
[Vosk](https://alphacephei.com/vosk/models). SHA-256 и размеры — в `models/sources.json`.

Расширение — явно выбранный `.py` с `process_frame(frame)`: BGR NumPy `uint8`
того же размера на входе/выходе. Процесс изолирует сбои и задержки, но не права
кода на файлы/сеть. Импорт проекта не включает расширения автоматически.

## Разработка и сборка

Используемая среда: Windows, Python 3.13, PyQt6.

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt pyinstaller
.venv\Scripts\python.exe tools\download_models.py
.venv\Scripts\python.exe main.py
.venv\Scripts\python.exe -m unittest discover -s tests -v
.\build.ps1
```

Сборка очищает пути DLL, сначала создаёт временную папку, проверяет EXE и только
потом заменяет предыдущую версию с сохранением резервной копии. Журнал:
`build/studio-build.log`. Расширенная проверка без устройств:

```powershell
.venv\Scripts\python.exe main.py --smoke-test --check-media --report build/health.json --render-ui build/studio-preview.png
```
